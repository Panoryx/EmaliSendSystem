# 验证报告

验证日期：2026-10-11。所有测试使用临时目录及测试凭据，没有真实邮箱授权码，没有向外部邮箱发送邮件。

## 功能验证

- Windows：`go test ./...`、`go vet ./...` 通过。
- Windows：`go test -race ./...` 通过。使用 MSYS2 UCRT64 的 64 位 GCC；机器原来的 MinGW 是 32 位，不能用于 amd64 race。
- Linux：设置 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64` 编译全部 8 个包的测试二进制，在 Ubuntu 20.04 WSL 中实际执行，全部通过。
- Windows 和 Linux 主程序均已编译。Linux 主程序实际启动并完成 API 压测，不需要服务器安装 Go SDK。
- OpenAPI 文档完成 JSON 解析、内部引用和路径检查。网络环境无法下载独立 OpenAPI validator，因此不宣称第三方完整规范校验已通过。

集成覆盖：并发幂等、队列条数和字节上限、账号预算及并发预留、北京日期预算重置、账号冷却、重试耗尽、任务取消、Token 撤销和越权、账号配置版本冲突、发送期间授权码更新、手动重发、后台调度器、重启恢复、正文与元数据过期清理、备份恢复、WAL 数据迁移快照、错误主密钥、重复初始化和进程锁。

SMTP 测试使用本地 TLS 服务器与动态生成的可信证书，覆盖隐式 TLS、STARTTLS、证书拒绝、认证失败、收件人拒收、限流、临时错误、正常接受、DATA 结束后断开导致的未知结果。账号连接测试确认不执行 MAIL 命令。

2026-10-11 实际 QQ 接入发现初版调用 go-mail 低层 SMTP Client 时遗漏信封地址的尖括号，导致认证成功但 MAIL 阶段返回 502。现已修正 MAIL FROM 与 RCPT TO 的 `<addr>` 格式，本地夹具严格拒绝裸地址，并增加两种 TLS 模式下的完整投递回归测试。运行日志同时增加脱敏的 stage 和 code，便于区分认证与信封/内容提交失败。该修复没有自动重发用户的历史任务。

## 压力测试

两种环境均限制进程 CPU 亲和性到 2 个逻辑核，应用设置 128MiB Go 内存软目标。机器整体内存没有限制到 2GB，不能视为阿里云实机验收。测试没有配置发信账号，因此任务会排队；这些结果验证入队、并发控制和队列上限，不代表真实 SMTP 吞吐。

使用 100 个客户端线程池，提交 200 个 1KiB 正文请求，节奏为 20 请求/秒。随后并发突发 100 个请求，再以 20 请求/秒提交 850 个请求直到队列满。

| 指标 | Windows amd64 | Ubuntu 20.04 WSL amd64 |
|---|---:|---:|
| 空闲内存 | 11.8MiB Working Set | 14.4MiB RSS |
| 观测峰值（包含最终读数） | 24.9MiB Working Set | 26.7MiB RSS |
| 20 请求/秒入队 p95 | 19.4ms | 8.1ms |
| 200 个节奏控制请求 | 全部 202 | 全部 202 |
| 100 个同时突发请求 | 40×202，60×429 | 42×202，55×429，3×503 |
| 后续 850 次提交 | 760×202，90×503 | 758×202，92×503 |
| 最终待发送队列 | 1000 条 | 1000 条 |

Linux 突发中 503 来自活跃 HTTP 请求上限；429 来自 Token 限流。最终队列 1000 条、正文总量 1,024,000 字节。容量拒绝后未继续扩大队列。

原始数据：`load-results-windows.json`、`load-results-linux.json`。测试是约一分钟的短时观测，未进行多小时稳定性测试、真实公网链路测试或服务商额度验收。
