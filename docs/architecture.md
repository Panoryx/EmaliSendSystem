# 架构与扩展说明

## 分层依赖

`domain` 仅依赖标准库，定义状态、邮件、账号、投递结果、Clock 和选择策略。`app` 使用 Repository 和 Cipher 接口编排业务。`httpapi` 仅接触应用服务及其端口。`store` 实现 SQLite 数据操作，`transport` 实现 SMTP。`cmd/emailsend` 是唯一组装入口。

接口定义在消费方，构造函数手动注入，不使用全局服务定位器。渠道工厂注册表仅在启动时写入，启动后只读。数据库映射私有，不把 SQL、事务和外部库错误暴露给业务或 API。

## 不可破坏的约束

- 入队事务包含幂等查询、容量检查和 INSERT；同 Token 并发提交不能创建重复任务。
- Claim 在同一事务中领取任务、锁定账号槽位、预留每日/分钟预算并插入尝试记录。SMTP 网络 IO 不在事务中执行。
- Finish 原子释放账号槽位、写尝试结论并转换状态。管理员停用优先于后台结果，版本号防止 PATCH 覆盖预算。尝试记录账号版本，旧凭据的认证失败不能覆盖发送期间刚更新的配置状态。
- 所有终态不可逆，重发创建新任务。结果不确定不能被适配器标记成普通临时失败。
- Token 授权范围在提交时保存；调度前再次检查是否已撤销。已开始的发送不会被撤销请求强行中断。
- 凭据与 Token 不进入 JSON 读响应、日志或原始异常；帐号 secret 存储为带版本用途认证的 GCM 密文。

## 新增邮箱服务商

使用 SMTP PLAIN/LOGIN 的邮箱只需要新增账号参数，不需要改 Handler 或新增 Transport。465 对应 implicit，587 对应 starttls；服务商预设可以作为配置默认值添加，预算仍由用户明确设置。

新增邮件发送 API 时：实现 `domain.MailTransport`；转换外部结果为 `domain.Result`；在启动注册表注册工厂；为渠道引入专用配置和对应管理契约；为适配器建立本地 HTTP fake 测试。不能忽略 API 结果不确定时的重复风险。

第一版账号字段针对 SMTP，后续 API 账号应新增类型化渠道配置及数据库迁移，不把 API 凭据塞入 SMTP host/username 字段。新增配置不得提供跳过 TLS 验证的生产选项。

## 替换账号选择或数据库

替换 `AccountSelector` 实现并在组装入口注入。资格、额度和并发由 Repository 原子控制，策略只负责候选者排序，不负责再次修改预算。

替换 SQLite 时实现 `app` 的三个 Repository；保留幂等唯一约束、容量检查、领取及预算预留的原子性、配置版本冲突、终态不可逆等行为。现有集成用例作为新存储的契约测试。

新增迁移必须提升 schema 版本，备份旧库，执行事务迁移，不修改已经发布的历史迁移。第一版迁移仅创建 v1 schema。

## 后续功能

附件、定时发送、短信分别扩展明确的业务契约和容量限制。短信使用独立 SMS 模型与渠道接口；不将短信参数塞入邮件正文。未来前端消费 OpenAPI；多用户需要重新设计拥有权、配额和账号可见性，不能直接把现有管理员入口开放给普通用户。
